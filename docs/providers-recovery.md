# SNS連携一覧の読み込み復旧

## リリースノート

SNS連携画面で一覧の取得に失敗したとき、見出しとプロフィールへ戻るリンクを残し、
消えないエラーと「もう一度読み込む」ボタンを表示します。
通信が復旧したら、ページを開き直さずに明示的な再試行で一覧を確認できます。

- 初回失敗・再失敗とも、読み込み状態とエラーを区別して表示します。
- Enter / Space による再試行に対応し、取得中の連打による重複リクエストを防ぎます。
- 再試行を操作した人のフォーカスを、成功時は見出し、再失敗時は再試行ボタンへ戻します。
  待機中に別の要素へフォーカスを移したり、別の場所をクリックした場合は移動しません。
- 一覧の取得と描画が完了するまで、連携・連携解除の操作領域を表示しません。
- 取得に成功した後は、隠れた再試行ボタンを再操作しても再取得しません。
  既存の連携解除後に更新された表示を、古い取得結果で戻さないためです。

## 対象範囲

この変更は既存の `GET /api/providers` の表示と復旧のみです。
自動再試行、プロバイダーの追加、アカウント連携・連携解除の自動実行は行いません。
最後の連携プロバイダーを解除できない既存のガードと、`POST /auth/link` フォームを維持します。

共通 `apiFetch`、401 のトップページへの遷移、TOKEN_ROTATED / DBSC の処理、
認証・セッション・Cookie・CSRF・API・DB・依存・Worker 設定は変更しません。
一覧の表示復旧は、実際の OAuth 連携やデバイス検証の成功を保証するものではありません。

- `providers-loader.test.ts`: 実ページのマークアップ、永続エラー、単一の pending read、
  再失敗・復旧、描画失敗、成功後の再取得抑止、フォーカス・ポインター操作を検証します。
- `scripts/providers-recovery-browser-smoke.mjs`: ビルド済み静的ページを
  320px / 1280px の合成ブラウザーで確認します。合成プロバイダーだけを使用し、
  fixture 外の HTTP / WebSocket リクエスト、認証フローへのアクセス、
  変更系リクエストを遮断します。OS レベルの通信隔離を保証するものではありません。
  一覧の GET 失敗・ネットワーク障害・再試行・401 の既存遷移、
  最後のプロバイダーの保護と既存のフォーム属性を確認します。
- 通常の lint / format / 型・全テスト・両 frontend build・API 文書同期を維持します。
  最終コミットの CI とレビューで結果を確認します。

本番のアカウント、OAuth プロバイダー、D1、Cloudflare 設定は合成 fixture の対象外です。
ローカル環境の依存取得やブラウザー起動が制限される場合は、その未検証範囲を PR に記録し、
最終 head の通常 CI で補完できるか確認します。未解決の必須チェックを回避してマージしません。
