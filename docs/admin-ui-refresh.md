# 管理・アカウント画面のデザイン更新

## 変更内容

- 管理画面のサイドバー、現在位置の表示、本文の余白と配色を統一しました。
- ダッシュボードの7指標を、システム概況・ログイン状況・アカウント制限にまとめました。数値は従来と同じ `/api/metrics` から取得します。
- 指標の明示更新、更新失敗時の再試行、連続クリックの抑止を追加しました。
- モバイルメニューに閉じる操作、Escape、フォーカスの循環と復帰を追加しました。画面幅の変更や履歴からの復帰ではメニューを閉じます。
- 絵文字による装飾と重複した説明見出しを減らしました。ユーザー数などの状態表示と、操作に必要な説明は残します。
- アカウント設定に共通ヘッダーとナビゲーションを設け、プロフィール、セッション、SNS連携、連携サービス、ログイン履歴、統計を同じ構成に揃えました。
- プロフィールはラベルと入力欄をまとめ、メールの変更不可表示、保存中の状態、削除確認を維持しました。
- セッションや連携サービスは行ごとに整理し、既存の操作・再試行・コピー・履歴の読み込みを維持しました。デバイス認証にも共通の配色と入力スタイルを適用しました。

認証方式、管理者権限、APIの仕様、データベース、デプロイ設定は変更しません。
ユーザーのログインページのマークアップ・ステータス判定とIdPの認証画面は、この変更の対象外です。参照サイトにだけある架空のプロフィール、サービス、状態表示や操作は追加しません。

## 検証

`reference-layout.test.ts` は実際のAstroテンプレートとクライアントスクリプトを使い、DOM上でメニュー、指標表示、更新失敗と再試行、連続操作を検証します。ブラウザによる描画確認の代わりではありません。

`ui-reference-browser-smoke.mjs` はビルド済みの管理画面を使い、1280×900px、390×844px、390×320pxでのログイン表示、モバイルメニュー、履歴移動と明示更新を確認します。管理ダッシュボードに加え、ユーザー一覧、サービス一覧、セキュリティ監視を合成データで読み込み、横はみ出し、現在のナビゲーションとスクロール領域のフォーカスを確認します。動的SVGにもグラフ内限定のCSSを適用し、配色と軸ラベルが描画領域に収まることを確認します。グラフは実幅を測って軸文字を12pxに保ち、サイズ変更時は取得済みデータだけを再描画します。アカウント設定6画面とデバイス認証は1280×900px、390×844px、320×740pxで読み込み完了と横はみ出しを確認します。ローカルの静的サーバーと合成APIのみを使用し、外部originへのリクエストと書き込みを遮断します。モバイルの選択中タブは水平スクロール内に表示し、ページの縦位置とフォーカスを保ちます。合成pageshowイベントによる検証は、実際のBFCache復帰と区別します。BFCacheの実復帰を観測できなかった場合はJSON記録に未確認として残します。CIではスクリーンショットとJSON記録を `ui-reference` artifactに保存します。

既存のプロフィール復旧・保存中の下書き、連携コピー、SNS連携復旧、ログイン履歴・統計、管理者監査ログなどのブラウザ回帰試験も継続します。
