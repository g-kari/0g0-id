# 管理者監査ログの閲覧（2026-10-02）

管理画面 `/security/audit` で管理者操作の記録を確認できます。
セキュリティ概況の「管理者監査ログを見る」から開きます。

## 使い方

- 操作者IDと対象IDは完全一致のUUID、操作は `user.ban` などの分類・操作名です
- 3条件はANDで組み合わせます。空欄は条件なし、候補にない有効な操作名も検索できます
- 「絞り込む」「リセット」は先頭ページへ戻ります。50件ごとに件数とページを表示します
- URLに条件とページを保持し、再読み込み・戻る・進むで復元します
- 取得失敗は「再読み込み」で同じ条件を再試行できます。入力不正を全件検索に置き換えません

表示するのは日時・操作者ID・操作・対象種別/ID・記録された成功/失敗です。
日時は閲覧端末のタイムゾーンで表示します。SQLiteのゾーンなし日時はUTCとして解釈します。
成功/失敗は監査記録の値であり、対象の現在の状態や監査の完全性を保証しません。
削除済みの対象も記録に残ります。ユーザー/サービスの有効なUUIDだけ既存の詳細へ
リンクし、削除済みの場合は詳細ページで見つからないことがあります。
未対応の対象種別や不正なIDにはリンクを作りません。

## 安全性と互換性

既存の管理者専用 `GET /api/audit-logs` を使用し、API・認証・権限・DB・依存に変更はありません。
取得は固定50件です。表示前にページ情報と各行の検索条件を確認します。
不正・重複・未知のURL条件、ページサイズの倍数でないoffsetは取得前に拒否します。
新しい検索は前のリクエストを中止し、遅れた成功・エラー・認証失敗を採用しません。

詳細JSON、IP、任意のサーバーエラー文は表示・コピー・ログ出力しません。
表示専用フィールドへ投影し、DOMはテキストとして組み立てます。
403には固定文、401にはログイン画面への遷移を使用します。
エクスポート・自動更新・管理操作ボタンはありません。

## 検証と範囲

入力/レスポンス/リンクの単体テストと、実SQLを使う使い捨てSQLiteで
複合条件・空結果・51件・同時刻の順序・一覧と件数を確認します。
`scripts/audit-logs-browser-smoke.mjs` はビルド済みAstro画面を合成データだけで検証し、
320/390/1280px、明暗の環境設定、キーボード、履歴、競合、認証エラー、再試行、
秘密文字列の非表示、安全なリンクを確認します。外部通信と変更系リクエストは遮断します。
CIの `audit-logs-ui` artifactに結果とスクリーンショットを保存します。
