# ログインイベントの絞り込み（2026-10-02）

管理画面 `/security/events` に、ユーザーID・国コード・OAuth プロバイダー・期間の
組み合わせ検索を追加しました。ユーザーIDは完全一致、国未取得のイベントは
`unknown` で検索します。期間は全期間（初期値）・直近24時間・7日・30日です。
「絞り込む」と「リセット」は先頭ページに戻ります。50件ごとのページング、
再読み込み、ブラウザーの戻る・進むでも URL の検索条件を保持します。

セキュリティ概況の疑わしい多国間ログインから「ログインを調べる」を選ぶと、
そのユーザーの直近24時間のイベントを開きます。既存のユーザー詳細リンクも利用できます。
取得失敗は画面に残し、「再読み込み」で同じ条件を再試行できます。
新しい検索を始めると前のリクエストを中止し、遅い旧レスポンスが表示を上書きしません。

## API

管理画面 BFF `GET /api/security-trends/recent-events` は、管理者専用 IdP
`GET /api/metrics/recent-events` に同じ検索条件を転送します。

| パラメーター | 値                                                    | 省略時         |
| ------------ | ----------------------------------------------------- | -------------- |
| `user_id`    | 英数字・`_`・`-`、1〜128文字、完全一致                | 全ユーザー     |
| `country`    | 大文字2文字の国コード、または `unknown`（DB の NULL） | 全ての国       |
| `provider`   | `google` / `line` / `twitch` / `github` / `x`         | 全プロバイダー |
| `period`     | `all` / `24h` / `7d` / `30d`                          | `all`          |
| `limit`      | 整数1〜100                                            | 50             |
| `offset`     | 0以上の安全な整数                                     | 0              |

条件は AND で結合し、一覧と総件数に同じパラメーター束縛 WHERE を使います。
期間の下限はリクエスト時刻からの UTC 経過時間で、境界を含みます。
SQLite 形式と ISO 形式の日時を同じ時刻として比較します。
既存の `created_at DESC, id DESC` 順と `{ data, meta: { limit, offset, total } }`
形式、フィルター未指定時の全件取得は維持します。
フィルター指定時だけ `meta.applied_filters`（`user_id` / `country` / `provider` は
未指定なら NULL、`period` は全期間なら `all`）を返します。画面はこれを照合し、
IdP と BFF の別々のデプロイ中に旧 API が検索条件を無視しても全件を表示しません。

不正値・空の明示指定・同名パラメーターの重複・未知のキー・2048文字を超える
クエリーは `400 INVALID_PARAMETER` です。誤った条件から全件取得へのフォールバックはしません。
既存の認証・管理者権限チェックは維持します。マイグレーション・依存更新はありません。

- 複合条件・全件・国未取得・空結果・51件以上のページング・ミリ秒境界
