# ログイン統計の期間切替と再読み込み

## 変更内容 2026年10月5日

`/login-stats` で期間を続けて変更したとき、古い応答が新しい期間の表示や読み込み状態を
上書きする問題を修正します。読み込みごとに世代番号を付け、最新の世代だけが
プロバイダー別統計、日別トレンド、空の結果、エラー、読み込み中の表示を更新します。
7日から90日を選び、その後7日に戻した場合も、最初の7日の応答を採用しません。

取得に失敗した場合は「もう一度読み込む」ボタンから同じ期間を再試行できます。
EnterとSpaceで操作でき、読み込み中の連打は重複した取得を開始しません。
再試行中も期間を変更でき、新しい期間が表示を所有します。自動再試行やフォーカス移動は
追加しません。読み込みとエラーには読み上げ用の役割を設定します。

プロバイダーとトレンドは両方の取得が完了してから表示します。片方の取得が失敗した場合や
描画処理が失敗した場合は、途中のカードを隠し、画面内で再読み込みできる状態に戻します。
ブラウザが期間を復元した場合は `pageshow` と応答の採用前に選択値を確認し、必要なときだけ
新しい期間を読み込みます。同じ選択値の `pageshow` は重複した取得や失敗後の自動再試行を
開始しません。

## 互換性と対象範囲

- 期間は既存の7日、30日、90日、365日。通常の初期値は30日です。
- 使用するAPIは既存の `GET /api/me/login-stats?days=...` と
  `GET /api/me/security/login-trends?days=...` です。
- 両APIが同じ選択期間を使い、既存の並び順、合計、プログレスバー、空の各セクションを維持します。
- `apiFetch`、認証、Cookie、TOKEN_ROTATED、DBSC、バックエンド、依存関係、デプロイ設定は変更しません。
- 通信の中断を正しさの前提にせず、古い通信が後で成功・失敗しても世代番号で表示への反映を防ぎます。
- 共有 `apiFetch` の401遷移は従来どおりです。ページの世代確認より前に処理されるため、
  古い通信の401リダイレクトを抑制する修正ではありません。

## 検証手順

通常の `vp check`、`vp test run`、user frontendの `astro build` に加え、
`scripts/login-stats-browser-smoke.mjs` でビルド済みの実ページを検証します。
このスクリプトは既存のPlaywright 1.57.0を使い、ループバック上の静的ファイルと
合成した2種類のGET応答だけを許可します。外部オリジン、予期しないAPI、変更系リクエストを
遮断し、実アカウントや認証情報を使いません。CIは既存の使い捨てブラウザ依存を再利用し、
結果とスクリーンショットを `login-stats-ui` artifactへ保存します。

回帰テストでは旧応答の成功・失敗・空の結果、7日から90日から7日への切替、
同期間の失敗と再試行、連打、再試行中の期間変更、両APIの9通りの結果、
片方だけ先に完了する応答、期間の復元、フォーカス、文字列のエスケープを確認します。
合成 `pageshow` の確認と実際の戻る・進む操作は区別して記録します。

## 公開前の確認

最終コミットのCIと必要な独立レビューを確認します。既存のfrontend auditが失敗している
場合、このUIの機能テストで合格扱いにせず、draftを維持します。auditの閾値や依存関係は
この変更では修正しません。合成ブラウザ検証は、本番の認証、実データ、配信反映の確認を
意味しません。
