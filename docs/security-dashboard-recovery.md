# セキュリティ監視の取得失敗からの復旧

## 変更内容（2026年10月11日）

管理画面 `/security/dashboard` の4項目で取得に失敗した場合、各項目の「再試行」から
同じGETを再取得できます。正常な項目は表示を保ち、再取得しません。
再試行はEnter・Spaceでも操作でき、取得中の連打は重複したリクエストを開始しません。
複数項目が失敗している場合、1項目が復旧しても残るエラーを表示します。
空の結果も成功として表示し、以前の失敗表示を消します。

読み込み状態は項目ごとに伝えます。再試行ボタンで操作した後は、成功時は項目の見出し、
再失敗時はボタンにフォーカスを戻します。取得中に他の要素へ移動した場合と初回取得では
フォーカスを移動しません。自動再試行・定期更新は追加しません。

## 範囲と確認

使用するAPI、30日・24時間・7日・上位20件の取得条件、データ、認証、共有 `apiFetch`、
TOKEN_ROTATED・DBSC・401遷移、依存関係、CI・配備設定は維持します。
Issue #256 の監視画面に対する限定的な復旧改善です。

通常の `vp check`、`vp test run`、admin frontend buildに加え、既存の
`scripts/security-events-browser-smoke.mjs` でビルド済みページを合成GET応答だけで確認します。
既存23ケースを保ち、320・390・1280pxの各幅に復旧・空の結果・独立した初回取得の
3ケースを追加します。外部オリジン、予期しないAPI、変更系リクエストは遮断します。
結果とスクリーンショットは既存 `security-events-ui` artifactへ保存します。

合成検証の成功は本人ログイン、本番データ、実環境への配信反映の確認を意味しません。
最終headのCI、独立レビュー、正式な承認条件を満たすまでdraftを維持します。
